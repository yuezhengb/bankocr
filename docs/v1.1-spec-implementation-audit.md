# BankOCR V1.1 设计规格实现审计

**审计日期：** 2026-08-09
**审计基线：** `docs/specifications/BankOCR_V1_Design_Specification_v1.1.docx` 与同名 PDF 以及 `v1.0_original.docx`
**审计对象：** 当前 `agent/v1-1-spec-audit` 分支上的 BankOCR V1 release candidate 代码、测试、打包脚本和已有 4 页 PoC 证据。

## 1. 结论先行

本仓库已经具备一个可运行的 V1 engineering release candidate，但**尚未通过正式 V1 Release Gate**。本轮审计发现的影响安全性、可追溯性和导出正确性的缺口已经先修复一批：

1. `TextBlock` 现在具有稳定 ID，字段具有多来源 `source_spans`，并可经过 SQLite round trip。
2. 原生 PDF 文本进入 Parser 前增加 Native Text Quality Gate；质量不可信时转 Rasterize + OCR，HYBRID 结果做基础去重。
3. Generic 关键列无法可靠映射时统一进入 `PAGE_REVIEW`，不再用普通 `FAILED` 把可恢复的人工确认路径隐藏掉。
4. 校验 Issue 增加 `PASS / FAIL / INDETERMINATE / NOT_APPLICABLE` 规则状态，并持久化到 Review/SQLite/导出层。
5. Transactions 表改为业务字段优先；每次 Excel + Review Excel + searchable PDF 导出都生成带文件大小和 SHA-256 的 `*.export-manifest.json`。
6. CLI 的 persisted run 使用当前 SQLite schema 版本，而不是硬编码旧版本；导出元数据包含源文件 SHA-256。

这些修复只能证明实现方向更接近 v1.1，不能把 4 页 PoC 的结果外推为任意银行、任意扫描质量的正式产品质量。当前正式门槛仍被 Golden Set、独立复核、全新断网 Windows 验收、签名和字体授权等外部证据阻塞。

## 2. v1.0 到 v1.1 的重要变化

v1.0 已经确定了 CPU-first、离线、页面分类、CoordinateTransform、Generic fail-closed、Decimal 校验、Silent Critical Error、Run pinning、SQLite checkpoint、Windows 打包和 benchmark 等总体方向。v1.1 不是简单改名，而是把以下容易造成“看起来能跑、但无法安全交付”的部分具体化：

| v1.1 增强 | 对实现的直接影响 |
|---|---|
| Native Text Quality Gate | 原生文本不能盲信；异常页面/区域必须 fallback 到 Rasterize + OCR，不能伪造 OCR confidence。 |
| 字段级 provenance | `ProvenanceValue` 从单一 bbox 扩为 `raw_blocks[] + source_spans[]`；一个字段可以对应多个原始块。 |
| Generic 首屏映射确认 | 关键列无法可靠映射时停在 `PAGE_REVIEW`；用户确认后生成 project/Run scoped Temporary Template。 |
| 交易结构复核 | 复核对象从单字段扩为字段 + 交易结构，支持移动、合并、拆分、补行和标记重复。 |
| 四态确定性校验 | 缺少前置余额、页面缺失或规则不适用不能简单当作 FAIL。 |
| anchor/table-local 坐标 | 模板坐标优先相对表格/表头锚点，page-relative 只能是 fallback。 |
| Export Manifest | 每次导出要记录 `export_id`、`run_id`、时间、未解决数量和三类输出的文件名/大小/hash。 |
| Benchmark 分层 | Calibration、Regression、Locked Release Holdout 分离，并按 statement/account/layout 做隔离，目标规模 500–1000 页。 |
| 发布硬化 | 离线安装、Authenticode、SmartScreen/Defender、SBOM/license、字体再分发授权和全新 Windows 验收成为正式门槛。 |

## 3. 要求—实现矩阵

状态含义：

- **已实现**：代码和自动化测试已有直接证据；不代表已通过正式发布数据集。
- **部分实现**：核心路径存在，但 v1.1 仍要求的覆盖、GUI 或外部证据尚未齐全。
- **未实现**：当前代码没有完整能力，不应在产品状态中写成 complete。
- **外部门槛**：代码可以提供脚本或接口，但必须由真实环境、授权方或独立人员产生证据。

| v1.1 主题 | 状态 | 当前证据 / 仍缺内容 |
|---|---|---|
| CPU-first、离线模型 manifest、SHA-256 | 部分实现 | RapidOCR/ONNX CPU、本地 Model Pack 和 hash 校验已存在；完整断网新机安装和供应链许可证仍待验收。 |
| PDF 页面分类、原生/扫描/HYBRID、旋转与坐标回映 | 已实现 | `pdf/`、`image/renderer.py`、CoordinateTransform 和页面级容错有测试。 |
| 流式处理、单页失败不拖垮整文档、内存上限 | 部分实现 | 页面 callback/checkpoint 已实现；正式 500–1000 页峰值 RSS 证据尚未形成。 |
| Native Text Quality Gate | 部分实现 | 已检查空层、异常字符、越界 bbox、异常高度和稀疏文本，并支持 fallback；还没有 v1.1 要求的关键字段覆盖率/页面视觉覆盖率/区域级 fallback 的完整门禁。 |
| HYBRID native/OCR 去重 | 已实现（基础版） | 相同归一化文本 + bbox IoU 去重且保留 native；对文本近似但不完全相同、分裂/合并块的覆盖仍需 Golden Set 验证。 |
| TextBlock 稳定 ID 与字段 source spans | 已实现 | `TextBlock.text_block_id`、`SourceSpan`、Parser 生成、SQLite v5 round trip、Source Index 已测试；旧数据库通过迁移兼容，任意外部调用者重复手工 ID 的全局唯一性仍需 API 层约束。 |
| raw / secondary / suggested / final 分层 | 已实现 | `FieldValue`、Secondary OCR、Review 和 Excel 分层保留；未审核值不会静默晋升为 final。 |
| Known Template wired/semi-wired/positional | 部分实现 | 已知样本布局已跑通；跨银行、跨版本和低质量扫描覆盖不足，不能据此宣称通用准确率。 |
| Generic fail-closed | **已实现（核心）** | 关键列缺失/歧义现在返回 `PAGE_REVIEW`；Temporary Template 已有 Run-scoped SQLite、CLI/Review GUI 确认和重跑接入；正式 holdout 仍待完成。 |
| 交易结构人工复核 | **已实现（核心）** | `ReviewSession`、SQLite schema v6、ReviewService 和 Review GUI 已支持移动、合并、拆分、补行、标记重复；source spans、review order、duplicate_of 和 review_events 已测试。 |
| 四态 Validation | 部分实现 | `ValidationRuleState` 已加入 Issue、Risk、SQLite 和 Review Excel；当前报告主要记录异常，不会为每条 PASS/NOT_APPLICABLE 规则生成独立结果，完整规则覆盖仍需补测试。 |
| Decimal、余额连续性、日期/账户/币种、重复/疑似漏行 | 部分实现 | 规则代码和 4 状态语义已有；正式 Silent Critical Error 评估仍依赖锁定数据集和人工 truth。 |
| Secondary OCR | 已实现（核心路径） | 只对疑似 bbox 做局部二次识别并保留 raw；需要在多银行/多扫描质量 holdout 上验证是否减少漏检而未引入静默错误。 |
| Excel 业务优先列 | 已实现 | Transactions 将日期、收支、余额、摘要、对手方、页码/状态放在技术列之前；Source Index 保留来源块、source spans 和规则状态。 |
| Export Manifest | 已实现 | CLI 和 PDF task queue 均写 `*.export-manifest.json`，记录三类输出 hash/size、源 SHA、run 和 unresolved 数量；重新导出生成新的 export manifest，不修改 Run Manifest。 |
| Searchable PDF | 部分实现 | PyMuPDF invisible text layer 和原始 PDF 不覆盖已有测试；v1.1 要求的 viewer benchmark 与 OCRmyPDF fallback 证据尚未完成。 |
| SQLite project/run/checkpoint/resume | 已实现（核心） | schema 已迁移到 v6，保存 TextBlock ID/source spans、source SHA、page 状态、结构复核、Temporary Template 和 review audit；活动数据库仍必须放在本地稳定目录，不能放网络共享目录。 |
| Run Manifest pinning | 部分实现 | run 启动时固定 engine/model/template/parser/rules/exporter/schema；Run Manifest 是版本钉死数据，源文件 hash 在 run/Export Manifest 中保存，时间等生命周期字段在 SQLite。 |
| Windows GUI 与 Review GUI | 部分实现 | 主窗口、任务队列、字段复核、结构复核控件、重新导出和 Generic 映射确认向导已有；新机断网安装与外部验收仍待完成。 |
| Temporary Template / 模板编辑工具 | **部分实现** | 已有 project/Run scoped 临时模板确认、schema v6 持久化、CLI/GUI 映射、模板优先应用、页面重排和恢复重跑；尚未自动转正式模板。 |
| anchor/table-local 模板坐标 | **未实现** | 当前 `ColumnDefinition` 仍以 page-relative ratio 为主；v1.1 的 table box/header anchor 优先坐标需要独立模型、模板 schema 和回归测试。 |
| Benchmark Calibration/Regression/Locked Holdout | 部分实现 | benchmark runner、资源和基础 gate 已存在；当前可复现证据只有 4 页/92 truth rows，尚未达到 500–1000 页、statement-level split 和独立 holdout。 |
| Windows 打包、签名、SmartScreen/Defender | 外部门槛 | PyInstaller fallback 和验证脚本已存在；Nuitka 主路线、Authenticode 正式证书、SmartScreen/Defender 分发验证、全新 Windows 安装/卸载仍待完成。 |
| SBOM、第三方许可证、CJK 字体授权 | 外部门槛 | SBOM/许可证文件生成路径已存在；法律/分发授权确认和随包字体的最终选择尚未归档。 |
| 隐私与安全目标 | 部分实现 | 默认无网络/无 telemetry、原始 PDF 不覆盖、日志避免业务全文的代码约束已有；这不是渗透测试、终端防护或组织级信息安全认证。 |

## 4. 本轮代码修复与验证

### 已修改的实现

- `src/bankocr/domain/text_block.py`：新增 `text_block_id` 和 `SourceSpan`。
- `src/bankocr/parser/models.py`、`parser/templates.py`：字段级 source spans 贯穿解析。
- `src/bankocr/pdf/native_quality.py`、`pipeline/processor.py`：原生文本质量门和 HYBRID 去重/回退。
- `src/bankocr/validation/engine.py`、`validation/risk.py`、`storage/project_store.py`：四态规则、风险映射和持久化。
- `src/bankocr/export/manifest.py`、`export/excel.py`、`export/review.py`、`cli.py`、`task/document_queue.py`：导出 hash manifest、业务优先列、规则状态和源文件 hash。
- `src/bankocr/parser/generic.py`：无法可靠推断的 Generic 页面进入可恢复 `PAGE_REVIEW`；`parser/temporary_template.py`、`template_cli.py` 和 `ProjectRunService` 提供确认后的 Run-scoped 重跑路径。
- `src/bankocr/gui/template_mapping.py`、`gui/app.py`：Review GUI 显示 OCR 块证据并要求显式确认列名、边界、required fields 和 Run-scoped Temporary Template。
- `src/bankocr/gui/review_model.py`、`pipeline/review_service.py` 和 `storage/project_store.py`：结构复核操作、schema v6、review order、duplicate_of 与审计快照。

### 需要保留的限制

当前 4 页基准结果（92 条 truth row、日期/金额/余额/行关联 100%、Review 0%、Silent Critical 0%、峰值 RSS 约 814 MB）仅说明已知样本 A/B 在当前环境的 PoC 表现。它不能证明：

- 任意银行模板都能正确解析；
- 低质量、旋转、遮挡、重复页、缺页和混合 PDF 都不会出现静默错误；
- GUI 结构复核、Temporary Template 和断点恢复已在当前开发机具备代码路径，但尚未在全新断网 Windows 上验收；
- 安装包、签名、字体和第三方许可已经可合法分发。

## 5. 正式 V1 尚未通过的原因

必须完成并归档以下证据，才能创建正式 V1 tag：

1. 500–1000 页、按 statement/account/layout 隔离的 Calibration、Regression、Locked Release Holdout；
2. 金额、余额、账号和关键结构由独立第二人复核，保留标注审计记录；
3. 全新、断网的 Windows x64 机器完成安装、运行、暂停/恢复、Review、Excel、searchable PDF、升级/回滚和卸载；
4. 所有发布 EXE 完成正式 Authenticode 签名，并有 SmartScreen/Defender/分发渠道结果；
5. CJK 字体再分发授权、第三方许可证和 SBOM 审查完成；
6. Native Quality Gate、Generic 映射确认、结构复核和 searchable PDF viewer/fallback benchmark 补齐；
7. 通过以上证据后再由负责人复核 release manifest、hash、版本和 tag。

因此当前正确标记是：**V1 engineering-complete / release-candidate；正式 V1 未发布。**
