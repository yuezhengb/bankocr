# BankOCR 结果整理与一键下载设计

## 目标

改善 Linux 网页服务的处理结果展示：让用户能快速区分不同结果文件，并在任务完成后一次下载全部结果。压缩包只包含程序生成的结果文件，不包含用户上传的原始 PDF。

## 范围

- 仅调整 `bankocr-server` 网页服务及其下载接口。
- 不改变 OCR、解析、校验和导出内容。
- 不改变 Windows GUI。
- 保留现有单文件下载链接，兼容已经生成的任务。

## 用户界面

每个处理任务显示为一个独立卡片：

1. 卡片顶部显示原始文件名和处理状态。
2. 任务完成后，顶部显示“下载全部结果 ZIP”主按钮。
3. 结果按用途分成四组：
   - **直接使用**：普通 Excel。
   - **和 PDF 对照**：PDF 原样 Excel、核对 PDF、可搜索 PDF。
   - **人工复核**：人工复核 Excel。
   - **处理记录**：摘要 JSON、导出清单 JSON。
4. 链接使用易懂的中文名称，保留实际文件名作为辅助信息，避免长文件名挤在一行。
5. 排队中或处理中不显示 ZIP 下载按钮；失败任务显示清晰的错误信息。
6. 卡片在窄屏下自动换行，按钮和链接保持可点击区域。

## ZIP 下载接口

新增 `GET /download/<job_id>/all.zip`。

- 只允许状态为 `completed` 的任务下载。
- 压缩包成员来自该任务已经登记的 `output_files`，不重新扫描任意目录。
- 每个成员只使用文件名作为 ZIP 内路径，禁止目录穿越。
- 不加入原始 PDF、SQLite 文件、临时文件或其他任务目录内容。
- 使用临时文件生成 ZIP，响应发送完成后自动清理，不在任务目录留下额外压缩包。
- 任务不存在返回 404，任务尚未完成返回 409，打包或读取失败返回 500。
- 返回 `application/zip` 和安全的下载文件名。

## 兼容与错误处理

- 保留原有 `/download/<job_id>/<filename>` 单文件接口。
- 结果文件缺失时不生成部分成功的压缩包，直接返回错误。
- 页面定时刷新逻辑保持不变，仍每 2 秒获取任务状态。
- 所有下载继续经过现有 Nginx HTTPS 和 Basic Auth 保护。

## 验收标准

1. 完成任务的页面按四组整齐展示结果，并显示“一键下载全部结果 ZIP”。
2. 点击 ZIP 后 HTTP 状态为 200，压缩包可正常打开。
3. ZIP 恰好包含该任务的全部结果文件，不包含原始 PDF 或其他任务文件。
4. 排队中、处理中任务不能下载 ZIP；不存在的任务返回 404。
5. 原有单文件下载仍返回 200。
6. 页面在桌面和窄屏窗口中都不出现横向挤压或文件名重叠。
7. 全部项目测试通过，并在 VPS 上完成一次无敏感信息的上传、处理和 ZIP 下载验证。
