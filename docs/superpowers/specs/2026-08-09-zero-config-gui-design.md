# BankOCR 零配置可视化版本设计

**日期：** 2026-08-09
**适用范围：** 离线 Windows x64 桌面使用
**状态：** 已获用户确认，待实施

## 1. 目标

把当前需要命令行参数的 BankOCR GUI 改造成面向普通员工的“零配置”桌面程序：员工双击程序后，只需要选择 PDF、点击开始、查看结果，不需要 PowerShell、Python、模型路径或数据库路径。

程序继续保持离线运行，原始 PDF 不覆盖，识别原文、建议值和人工最终值分开保存。

## 2. 方案选择

考虑过三种方式：

1. **当前 GUI 增加自动配置（选定）**：保留现有处理队列、复核和 Temporary Template 能力；启动时自动发现程序旁边的模型与模板；改动最小，便于继续验证。
2. 单独增加一个启动器：可以隐藏参数，但会增加一个额外程序和故障点。
3. 先做完整安装程序：使用体验更完整，但需要额外进行安装、卸载、签名和新机器验证，不适合作为当前第一步。

本阶段采用方案 1，之后可以在所有外部发布门槛通过后再制作安装程序。

## 3. 普通员工使用流程

程序启动后显示清晰的三步提示：

1. **选择 PDF**：支持按钮选择和拖拽 PDF。
2. **开始处理**：显示文件名、状态、页数和需要复核的数量。
3. **查看结果**：提供“打开结果文件夹”“打开 Excel”“打开可搜索 PDF”“开始人工复核”按钮。

处理完成后，程序不要求员工查看 JSON 或 SQLite。若识别结果需要人工确认，界面用中文明确提示需要复核的数量；保存复核结果后自动重新导出 Excel、复核文件和可搜索 PDF。

复杂的 OCR 参数、模型版本、模板路径、项目数据库路径不出现在普通界面中。

## 4. 自动目录规则

程序使用 Windows“文档”目录作为根目录；若 Windows 文档目录无法取得，则退回当前用户的 `Documents` 目录。程序自动创建：

```text
文档\BankOCR\
├── 输出\
├── 项目\project.sqlite3
└── 日志\
```

每个输入 PDF 使用独立结果目录，目录名包含原文件名和时间，避免覆盖以前的结果：

```text
文档\BankOCR\输出\<原文件名>-<时间>\
├── <原文件名>.xlsx
├── <原文件名>.review.xlsx       （有复核项目时）
├── <原文件名>.searchable.pdf
├── <原文件名>.summary.json
└── <原文件名>.export-manifest.json
```

原始 PDF 仍留在员工选择的位置，程序不会覆盖或移动原始文件。

## 5. 安装包与资源发现

发布目录保持自包含，至少包含：

```text
BankOCR\
├── bankocr-gui.exe
├── models\
├── templates\known\
└── fonts\             （若使用随包字体）
```

双击启动时，程序以可执行文件所在目录为资源根目录，自动定位 `models`、模型 manifest、`templates\known` 和字体。资源缺失时不静默失败，而是显示中文错误对话框，指出缺少的目录或文件，并提示联系管理员重新复制完整安装包。

命令行参数保留为内部诊断和自动化测试的兼容入口，但普通员工不需要使用它们。

## 6. 错误处理与人工复核

- PDF 不存在、损坏或没有读取权限：显示“无法读取文件”和具体文件名。
- 模型、manifest、模板或字体缺失：显示“程序包不完整”，不启动半成品处理。
- 输出目录没有写权限：显示“无法保存结果”，并给出输出目录位置。
- 单页识别失败：保留已完成页，任务显示需要复核或失败，不伪造通过结果。
- 未知流水格式：进入 Generic fail-closed 或 Temporary Template 流程，不自动写入正式模板。
- 处理过程中关闭窗口：阻止直接退出，提示先等待完成或取消。

所有错误保留在本地日志和 Run Manifest 中，界面显示简明说明。

## 7. 安全与数据边界

- 默认完全离线；不请求网络、不上传 PDF、不发送 telemetry。
- 模型、模板和规则版本在每次 Run 中锁定。
- 原始 OCR、二次 OCR、解析建议和人工最终值分层保存。
- 金额继续使用 `Decimal` 和现有确定性校验规则。
- 复核保存后重新执行校验并重新导出，不直接覆盖证据链。
- 本阶段面向离线桌面使用，不宣称已满足正式公开发布要求。

## 8. 实施后的验收

在当前机器上至少验证：

1. 双击或无参数启动 `bankocr-gui.exe` 能打开主窗口。
2. 选择真实 PDF 后能在 `文档\BankOCR\输出` 下生成独立结果目录。
3. Excel、可搜索 PDF、summary 和 export manifest 能生成。
4. 需要复核时可从主窗口打开复核界面并保存结果。
5. 缺少模型或模板时能显示清晰错误，而不是无提示退出。
6. 现有自动化测试、离线模型校验和真实样本处理继续通过。

## 9. 明确保留的未验证项目

以下项目不能由本地代码测试替代，继续保留在 `docs/v1-release-gate.md` 和发布记录中，不能标记为已通过：

- 500–1000 页锁定 Holdout 和完整人工 truth；
- 独立第二人复核；
- 全新 Windows x64 机器或全新 VM 快照的断网验收；
- Authenticode 正式代码签名；
- SmartScreen 和 Defender 的外部验证；
- 随包字体的重新分发授权；
- 第三方依赖许可证和 SBOM 的正式审查；
- Temporary Template 自动晋级为正式模板；
- 所有银行版式的 anchor/table-local 坐标级覆盖。

完成这些外部项目之前，产物名称继续使用 `release-candidate`，不称为正式 V1 发布版。
