# BankOCR V1.1 Specification Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 对照已锁定的 BankOCR V1.1 设计基线审阅当前 release candidate，修复会影响安全性、可追溯性和用户导出结果的实现缺口，并把设计源文件和审计证据纳入仓库后推送 GitHub。

**Architecture:** 保持当前 PDF → TextBlock → Parser → Transaction → Validation → Review → Export 的分层。新增的稳定文字块身份、字段 source spans、Native Text Quality Gate、四态规则结果和 Export Manifest 都从领域模型向下游传递，不在 GUI 或导出层临时拼接。无法在当前环境完成的 Windows 代码签名、500–1000 页 Locked Holdout、SmartScreen/Defender 和字体再分发授权，记录为发布外部门槛而不是伪造为已完成。

**Tech Stack:** Python 3.12；PyMuPDF；OpenCV；RapidOCR/ONNX Runtime；SQLite；openpyxl；PySide6；pytest；PowerShell；Git。

## Global Constraints

- 原始 PDF 永不覆盖。
- 关键字段保持 raw / secondary / suggested / final 分层。
- 金额使用 `Decimal`，不使用二进制 float。
- Generic 和 Native Text 的不确定性必须 fail-closed 或 fallback，不能静默变成可信最终值。
- 日志和诊断不默认写入 OCR 全文、账号、姓名和金额。
- 同一 Run 的模型、模板、parser、rules、exporter 和 schema 版本固定。
- 真实 PDF、ground truth、OCR 全文和输出业务数据不得提交仓库。
